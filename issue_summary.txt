Issue:-
Terraform configuration was failing during validation and planning because of incorrect CloudFront/S3 policy configuration and an invalid backend setup.

Root Cause
The backend in backend.tf was initially configured to use a non-existent S3 bucket, causing:
NoSuchBucket: The specified bucket does not exist
The CloudFront OAC block in main.tf had incorrect string quoting earlier, which caused Terraform parse errors.
The S3 bucket policy in main.tf referenced:
aws_cloudfront_origin_access_control.s3_oac.iam_arn
but that attribute does not exist for this resource type, which caused:
Unsupported attribute
The CloudFront distribution resource in main.tf was also previously incomplete and missing its closing braces.
Action with command :-
I ran the following verification steps:
terraform validate
terraform init -reconfigure
terraform validate
and fixed the issues by:
changing the backend to a local state backend in backend.tf
correcting the OAC block values and quoting in main.tf
replacing the invalid bucket policy principal with:
Principal = {
  Service = "cloudfront.amazonaws.com"
}
completing the missing closing block in the CloudFront distribution resource
Conclusion (Summary)
The project was failing because of multiple Terraform configuration issues: a bad remote backend bucket, 
invalid CloudFront OAC string values, and an unsupported attribute in the S3 bucket policy. After fixing those errors, Terraform validation passed successfully with:
Success! The configuration is valid.
This means the configuration is now syntactically valid and ready for terraform plan or deployment.
